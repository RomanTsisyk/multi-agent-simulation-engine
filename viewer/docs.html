Overview

WarGame is a multi-agent AI simulation of the Suwalki Gap Crisis — a geopolitical flashpoint where Russia attempts to open a land corridor from Belarus to Kaliningrad through Lithuanian territory. Each country is played by an LLM-powered agent with multiple internal factions that debate policy before producing unified decisions. An impartial Game Master adjudicates all actions simultaneously.

Key Features

  • Realistic faction debates — hawks, doves, diplomats, military realists argue before each country acts
  • Anti-groupthink mechanisms — mandatory disagreement, red-line defense, forced risk identification
  • Fog of war — intelligence briefings contain deliberate inaccuracies and gaps
  • Cascading world effects — oil prices, NATO alert levels, morale, sanctions propagate automatically
  • Nuclear escalation ladder — peacetime → elevated → dispersal → launch_ready → tactical_use
  • Cross-round memory — each round references previous developments for narrative continuity
  • Dark-themed web viewer with real-time auto-refresh, charts, and per-country debate logs
  • Local or cloud LLMs — Ollama (free, local GPU) or DeepSeek API ($2-3/game)

System Requirements

  • macOS or Linux (tested on Mac Studio M2 Ultra 64GB)
  • Python 3.12+
  • Ollama (for local inference) or DeepSeek API key (for cloud)
  • ~20GB disk for model download (Ollama)
  • Recommended: 64GB+ RAM for 32B parameter models

Quick Start

1. Install Dependencies

pip install aiohttp pyyaml   # or: pip3 install aiohttp pyyaml

2. Set Up LLM Backend

Option A: Ollama (Local, Free)

# Install Ollama: https://ollama.ai
ollama pull deepseek-r1:32b          # Download model (~20GB)
ollama serve                          # Start server (default port 11434)

# For parallel processing (recommended):
OLLAMA_NUM_PARALLEL=4 ollama serve

Option B: DeepSeek API (Cloud, Fast)

export DEEPSEEK_API_KEY=your_key_here

3. Run the Game

# Quick test (2 rounds, 4 countries)
python3 run.py --rounds 2 --countries PL RU US DE

# Key NATO vs Russia players (5 rounds)
python3 run.py --rounds 5 --countries PL RU US DE FR GB LT

# Full scenario (10 rounds, 20 countries)
python3 run.py

# Cloud backend
python3 run.py --backend deepseek

4. View Results

python3 serve.py                     # Start viewer on port 8080
open http://localhost:8080            # Open in browser

Engine Architecture

Game Loop

Each round represents 12 hours of game time. The engine runs these steps sequentially:

1
Situation Briefing

Game Master generates a narrative briefing based on current world state and previous round summary.

2
Private Intelligence

Each country receives tailored intelligence with fog-of-war (deliberate inaccuracies, confidence levels, gaps).

3
Faction Debate (3 rounds)

Round 1: Initial positions. Round 2: Rebuttals with mandatory disagreement. Round 3: Final synthesis with risk identification.

4
Unified Decision

Country agent synthesizes the debate into 1-3 concrete actions + diplomatic messages.

5
GM Resolution

Game Master simultaneously resolves all country actions, checking for conflicts, realism, force ratios.

6
World State Update

Cascading effects: markets, morale, supply, NATO alert, nuclear posture, sanctions auto-propagate.

7
End Condition Check

Check for Russian corridor hold, NATO liberation, ceasefire, nuclear detonation, or NATO collapse.

World State Fields

Military
  • military_units — List of all deployed units (name, country, type, location, readiness 1-10, strength 1-10, casualties, supply_level 1-10, morale 1-10)
  • military_alerts — Per-country alert levels
  • corridor_control — "russian", "nato", or "contested"

Logistics & Attrition Rules

  • Units in combat lose supply_level by 1-2 per round
  • Supply ≤ 3 → -1 readiness per round
  • Supply ≤ 1 → cannot conduct offensive operations
  • Casualties ≥ 2 → -1 morale per 2 casualty points (delta-based, not compounding)
  • Morale < 3 → risk of unit refusing orders
Economic
  • markets — oil_price, euro_usd, gas_price_eu, stock_indices
  • sanctions — List of {from, target, type} (auto-deduplicated)
  • trade_disruptions — List of disruption events
Diplomatic
  • diplomatic_relations — Country → Country → -10..+10
  • treaties_invoked — List of invoked treaties (e.g. "NATO Article 5")
  • un_resolutions — List of UN resolutions
  • nato_alert_level — normal / elevated / high / article5
  • nato_consensus — Country → position text
Nuclear
  • nuclear_posture — Per-country: peacetime → elevated → dispersal → launch_ready → tactical_use → strategic

Auto-Escalation Rules

  • If any nuclear state escalates past dispersal, all nuclear states auto-escalate to at least elevated
  • Nuclear posture at launch_ready+ causes -5% war support (one-time penalty)
  • De-escalation occurs when no provocative events detected
Public Opinion & Humanitarian
  • public_opinion — Per-country: war_support (0-100), government_approval (0-100)
  • refugee_flows — List of {from, to, count, status}
  • humanitarian_crisis_level — Per-country: 1-10
Cyber & Infrastructure
  • cyber_operations — List of {attacker, target, type, severity, infrastructure_affected}
  • infrastructure_status — Per-country: power_grid, comms, financial, military_c2 (each 1-10)

Agent System

How Decisions Are Made

Each country has 1-4 internal factions (e.g. hawks, doves, military realists, diplomats). Before a country acts, its factions hold a 3-round internal debate. This produces realistic, nuanced policy decisions with genuine internal tensions.

Round 1: Initial Positions

Each faction independently states its recommended course of action based on the current situation, its personality, priorities, and red lines.

Round 2: Rebuttals

Each faction reads all Round 1 positions and responds. Anti-groupthink rules: must identify at least ONE disagreement, defend red lines explicitly, point out risks others ignore.

Round 3: Final Statements

Closing positions with mandatory concessions AND remaining objections. Forced risk identification ensures minority views are preserved.

Synthesis

After the debate, a neutral synthesis agent distills all positions into a unified decision:

  • DECISION — 1-2 sentence summary of the country's chosen course
  • ACTIONS — 1-3 concrete, specific actions (military moves, diplomatic messages, economic measures)
  • DISSENT — Notable minority positions that were overruled
  • DIPLOMATIC_MESSAGES — At least 1 message to another country or organization

Crisis Phase Detection

The debate system automatically detects the current crisis phase and adjusts faction weights:

  • Diplomatic (default) — diplomats and economic advisors get more weight
  • Hybrid (cyber/disinformation keywords) — wildcards and intelligence get more weight
  • Conventional (combat keywords) — military realists and hawks dominate
  • Nuclear (nuclear keywords) — pragmatists and doves dominate, hardliners marginalized

Adding a New Country

  1. Create countries/your_country.yaml following the schema in the Agents section
  2. Set code to a unique 2-3 letter identifier
  3. Define 1-4 factions with realistic personalities, priorities, and red lines
  4. Set military_strength and economic_strength on 1-10 scale relative to existing countries
  5. The country will be auto-discovered at game start

Adding a New Backend

  1. Create backends/your_backend.py
  2. Implement LLMBackend abstract class from backends/base.py
  3. Required methods: generate(system_prompt, messages, temperature, max_tokens) -> str and close()
  4. Register in run.py backend selection logic

Adding a New Scenario

  1. Create scenarios/your_scenario.yaml following suwalki_gap.yaml format
  2. Define: name, description, background, initial_event, game_time_per_round, total_rounds
  3. Define end_conditions with unique IDs, types, and check logic
  4. Define initial_world_state with military units, markets, diplomatic status, public opinion
  5. Update config.yaml: set game.scenario to your new file

Key Design Decisions

  • Delta-based morale — casualty penalties track what's already been applied, preventing compounding across rounds
  • List deduplication — sanctions, treaties, cyber ops auto-deduplicate to prevent unbounded growth
  • Cross-round memory — single summary string replaced each round (not growing context)
  • Decision condensing — debate logs stripped before sending to GM to save context window
  • Anti-groupthink — mandatory disagreement and forced risk identification prevent faction echo chambers
  • Fog of war — intelligence briefings contain deliberate inaccuracies, contradictions, and gaps
  • Dynamic faction weights — crisis phase auto-detected, faction influence adjusted accordingly

Performance Tips

  • Start with 4 countries for testing (--countries PL RU US DE)
  • Use OLLAMA_NUM_PARALLEL=4 ollama serve for local parallel processing
  • DeepSeek API is significantly faster for full games (15 min vs 2-4 hours)
  • Reduce debate.rounds to 2 for faster but less nuanced results
  • Lower max_tokens_per_response for faster but shorter faction responses
  • Set num_ctx: 8192 for smaller models with limited context

Critical Bugs

BUG: Strength reduction compounds every round (CRITICAL)

File: engine/world_state.py, lines 543–548

Problem: In _apply_cascading_effects(), the strength reduction formula strength_reduction = unit.casualties // 2 reapplies the full reduction every round rather than tracking what has already been applied. A unit with 4 casualties loses 2 strength per round indefinitely, rapidly dropping all units to strength 1.

# Current (buggy) - runs EVERY round, compounds
for unit in self.military_units:
    if unit.casualties >= 2:
        strength_reduction = unit.casualties // 2
        unit.strength = max(1, unit.strength - strength_reduction)

# Fix: track applied reduction like morale does
strength_reduction = unit.casualties // 2
already_applied = getattr(unit, '_last_casualty_strength_applied', 0)
new_penalty = strength_reduction - already_applied
if new_penalty > 0:
    unit.strength = max(1, unit.strength - new_penalty)
    unit._last_casualty_strength_applied = strength_reduction

Impact: All combat units become ineffective within 2–3 rounds regardless of actual damage. This is the highest-priority bug to fix.

BUG: Corridor control keyword matching is unreliable (CRITICAL)

File: engine/game.py, lines 821–875

Problem: Substring matching for terms like "seized" and "liberated" can match inside other words or in the wrong context. This directly affects game-ending conditions.

Fix: Use regex word-boundary matching (\bseized\b) with confidence scoring instead of in substring checks.

BUG: Nuclear escalation conflates posture with detonation (HIGH)

Files: engine/game.py lines 581–584, engine/world_state.py lines 645–648

Problem: The tactical_use posture level triggers game end, but posture is not the same as actual detonation. Countries cannot escalate to launch_ready without approaching an automatic game-over state.

Fix: Restructure to separate posture from action: peacetime → elevated → launch_ready → detonation_occurred. Only actual detonation should end the game.

BUG: Nuclear auto-escalation yo-yos (HIGH)

File: engine/world_state.py, lines 551–564

Problem: De-escalation and auto-escalation rules can conflict, causing nuclear posture to oscillate between rounds.

BUG: Silent unit update failures in GM resolution (HIGH)

File: engine/game_master.py, lines 373–386

Problem: When the Game Master references a unit that does not exist, the update is silently dropped with no warning or log entry. This can cause GM decisions to have no effect.

Fundamental Design Limitations

No Combat Resolution Model

There is no deterministic or probabilistic combat resolution system. Military outcomes depend entirely on LLM narrative judgment. There are no force ratios, terrain modifiers, or air superiority mechanics. The GM decides who wins engagements based on prose, not math.

Impact: Military outcomes can be inconsistent across runs. A weaker force may defeat a stronger one without explanation.

Recommended fix: Implement a force-ratio calculator with terrain, supply, air control, and morale modifiers that constrains GM resolution.

Diplomacy Is Narrative-Only

Countries state diplomatic positions in free text. Ceasefires and treaties are detected via keyword matching in GM output, not through a structured proposal/counteroffer system. This means diplomatic convergence is hard to track or verify.

Files: engine/game.py (corridor control detection), engine/game_master.py (resolution prompts)

Military Mechanics Dominate

The world state has detailed military tracking (units, supply, casualties, readiness) but economic and cyber mechanics are shallow. Sanctions are one-directional (no cost to the sanctioner). Cyber operations are purely narrative.
